# edgar-diff: SEC 10-K Disclosure-Change Panel

A small research-infrastructure project that builds a firm-year panel of
year-over-year textual change in Item 1A (Risk Factors) of SEC 10-K
filings, in the spirit of the disclosure-change literature (Cohen, Malloy
& Nguyen, "Lazy Prices," *Journal of Finance*, 2020). It pulls consecutive
10-Ks for a firm universe directly from SEC EDGAR, extracts the Risk
Factors section from raw filing HTML, and measures change with cosine
similarity and Jaccard token overlap. An optional secondary check
correlates that change score with each firm's stock return in the trading
days after the filing, benchmark-adjusted, as a directional sanity check.

This is proof-of-work infrastructure, not a finished empirical paper.
It's built to make the hard, boring parts of this kind of research
(reliable section extraction from inconsistent HTML, correct filing-date
alignment, event-window construction) solid enough that the panel it
produces is trustworthy to build on.

## Why this exists

Section extraction from EDGAR HTML and firm-year panel construction are
exactly the kind of unglamorous data-engineering steps that eat weeks of
an RA's time and are easy to get subtly wrong in ways that don't throw an
error. This project treats that as the actual problem to solve:

- **No silent failures.** Every extraction is tagged with a confidence
  level (`high` / `low` / `none`) rather than a binary hit/miss, and every
  panel row carries a `flagged` column with a reason, so a low-confidence
  extraction or an implausible year-over-year swing is visible in the
  output instead of quietly corrupting a downstream regression.
- **A real bug, found and regression-tested.** SEC's paginated submissions
  JSON is a set of parallel arrays; older pages sometimes have a `reportDate`
  array shorter than the others for that page. Padding only after
  concatenating all pages silently misaligns every later filing's fiscal
  year. The fix pads each page to its own length *before* concatenation —
  see `test_fetch_filing_index_handles_short_reportdate_on_older_page` in
  `test_pipeline.py`.
- **A TOC false-positive, found and guarded.** A compact table-of-contents
  block (`Item 1A ... Item 1B ... Item 2 ...`) can satisfy a naive
  start/end anchor match without containing any actual risk-factors prose.
  `_looks_like_toc()` checks anchor density in the head of a candidate
  match to reject this — see `test_extract_rejects_toc_style_false_positive`.
- **Event windows aligned to the actual filing date**, not a fixed
  calendar quarter, since the market can only react after the filing
  happened. Returns are computed from the first trading day strictly
  after `filing_date`, and reported alongside a benchmark-adjusted excess
  return so the correlation isn't just picking up market beta.

## Methodology

1. `EdgarClient` resolves ticker → CIK from SEC's `company_tickers.json`
   and pulls each firm's full filing history from the submissions API,
   paginating through older filings for high-volume filers.
2. `extract_item_1a_detailed()` extracts Item 1A from raw HTML via
   anchor-pattern matching across three confidence tiers (see docstring
   in `pipeline.py`).
3. `build_panel()` assembles firm-year pairs, computes TF-IDF cosine
   similarity and Jaccard token overlap between consecutive years'
   Item 1A text, and flags rows with low-confidence extractions or
   structurally implausible swings.
4. `validate_against_forward_returns()` is an optional secondary check:
   raw and benchmark-adjusted stock return over a fixed trading-day
   window starting the day after each filing, correlated against the
   change score.

## Known limitations

- Section extraction is regex/anchor-based, not a parsed document tree.
  It handles the common filing formats well but is not a substitute for
  spot-checking flagged rows against the source filing.
- The return validation is a directional sanity check, not a
  risk-adjusted asset-pricing test — no size/value/momentum controls
  beyond a single benchmark subtraction, and no handling of delisted or
  acquired firms.
- Firm counts in the default universe are far too small to make any
  correlation from this alone statistically meaningful; treat it as a
  plausibility check, not a finding.

## Running it

```bash
pip install -r requirements.txt

# CLI: builds the panel, saves results/panel.csv and a chart
python run_demo.py "Your Name your_email@school.edu"

# with forward-return validation
python run_demo.py "Your Name your_email@school.edu" --validate

# interactive app
streamlit run app.py
```

SEC requires a real, identifiable `User-Agent` (name + email) on every
request — the client fails fast with a clear error if one isn't provided.
Filing responses are cached on disk by default (`.edgar_cache/`), since
filings don't change once filed.

## Tests

```bash
pytest test_pipeline.py -v
```

14 offline unit tests, no network access — SEC responses are
monkeypatched. Covers user-agent validation, ticker-to-CIK parsing,
all three extraction confidence tiers (including the TOC false-positive
regression), the pagination-alignment fix, and trading-day return-window
construction.

## Project structure

```
pipeline.py        # EdgarClient, extraction, panel construction, validation
app.py              # Streamlit UI
run_demo.py         # CLI: run the pipeline, save CSV + chart
test_pipeline.py    # offline unit tests
requirements.txt
```
